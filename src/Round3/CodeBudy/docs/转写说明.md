# 转写说明

本文档说明从 Python/pygame 到 C++/DirectX 11 的转写决策、与原版的差异以及资源处理方式。

## 一、技术选型

按用户要求「使用本机自带的 C++ 版本和工具」，经探测确认本机环境后选型如下：

| 项目 | 选择 | 依据 |
|------|------|------|
| 编译器 | MSVC 14.51（Visual Studio 18 Community） | 本机自带 |
| 构建工具 | CMake（4.3.3） | 本机自带 |
| 图形 API | **DirectX 11** | Windows SDK 10.0.26100.0 内置 `d3d11.h`/`d3dcompiler.h`/`dxgi.h` 及对应 `.lib`，无需旧版 June 2010 SDK |
| 图片解码 | WIC（Windows Imaging Component） | DirectX 无内置图片加载，WIC 可解码 PNG/GIF |
| 音效 | PlaySound（`winmm.lib`） | 系统内置，可播放 WAV |
| 窗口/输入 | Win32 API | 标准桌面窗口 |

> 本机未安装旧版 `Microsoft DirectX SDK (June 2010)`，但现代 Windows SDK 已完整包含 DirectX 11 开发能力，因此按用户优先级直接采用 DirectX 11，无需降级到 OpenGL/Vulkan/GDI/GDI+。

## 二、渲染模型

- **坐标系**：采用正交投影，顶点直接使用像素坐标（左上角为原点），与 pygame 坐标系完全一致；常量缓冲区 `scale=(2/w, -2/h)` + `offset=(-1, 1)` 完成到裁剪空间的转换。
- **绘制单位**：每个精灵绘制为一个带纹理的四边形（两个三角形），顶点含 `position + uv`。
- **绘制尺寸 vs 碰撞尺寸**：`textureW/H` 存纹理原生尺寸（对应 pygame `blit` 按原生尺寸绘制），`rect` 存碰撞尺寸。二者通常一致，但墙体（50×50）爆炸时爆炸帧为 40×40，按原生尺寸绘制以忠实还原。
- **采样**：使用点采样（`D3D11_FILTER_MIN_MAG_MIP_POINT`），避免像素风贴图边缘插值产生杂色。
- **混合**：标准 alpha 混合（`SRC_ALPHA, INV_SRC_ALPHA`），支持 PNG/GIF 透明背景。
- **着色器**：HLSL 以内嵌字符串编译（`D3DCompile`），避免外部 shader 文件路径问题。

## 三、关键转写决策

| 原版实现 | C++ 转写 | 说明 |
|----------|----------|------|
| `pygame.sprite.Group` | `std::vector<std::unique_ptr<T>>` | 智能指针管理生命周期 |
| `time.sleep(0.05)` 线程阻塞爆炸 | `updateExplosion(dt)` 帧计时 | **非阻塞**：累计时间每 0.05s 推进一帧 blast1~8 |
| `pygame.image.load` | WIC 解码（GIF 取首帧） | 本项目 GIF 均为静态单帧，首帧足够 |
| `pygame.mixer.music` | `PlaySoundW(..., SND_ASYNC)` | 单通道异步播放，语义与原版单音乐通道一致 |
| 键盘事件 | `WM_KEYDOWN/WM_KEYUP` 转发 | 用 `lParam & 0x40000000` 检测按键重复，空格仅在首次按下发射 |
| `random.randint` | `rand()` 封装 `RandomInt()` | 首次调用自动 `srand(time)` 种子 |
| `os.listdir` 排序资源 | 显式路径数组 | 避免依赖目录遍历顺序，更可控 |

## 四、与原版的差异

### 1. 修复：敌方坦克初始位置

原版 `Enemy.__init__` 未设置坐标，5 辆敌方坦克会重叠在 `(0,0)`。转写时按索引将敌方坦克均匀分配到屏幕顶部（`y=0`，`x` 等间距分布）。

### 2. 修复：爆炸动画阻塞

原版用「线程 + `time.sleep(0.05)`」逐帧加载爆炸图，会阻塞主线程且存在线程安全隐患。转写为基于帧计时器的非阻塞动画，视觉节奏一致（每帧 0.05s，共 8 帧约 0.4s）。

### 3. 子弹尺寸

原版 `settings.py` 中 `BULLET_RECT = Rect(0,0,5,5)` 实际未被使用，子弹尺寸来自图片 `bullet.png`（实测 **3×3**）。转写采用 3×3。

### 4. 精灵实际尺寸（实测资源）

| 资源 | 实测尺寸 | 对应常量 |
|------|---------|----------|
| 坦克（hero/enemy GIF） | 40×40 | `TANK_SIZE` |
| 子弹（bullet.png） | 3×3 | `BULLET_SIZE` |
| 墙体（walls/*.png） | 50×50 | `BOX_SIZE` |
| 爆炸帧（blast*.gif） | 40×40 | `BOOM_SIZE` |

### 5. 音效 `hit.wav`

原版 `settings.py` 声明了 `HIT_MUSIC` 但代码从未播放，且源资源目录中**并不存在** `hit.wav` 文件。转写保留该常量声明（忠实原版），但不播放、不依赖该文件。

### 6. 窗口不可缩放

与 pygame 默认窗口一致，使用固定尺寸窗口（`WS_OVERLAPPED | WS_CAPTION | WS_SYSMENU | WS_MINIMIZEBOX`）。

### 7. 游戏结束表现

- 老巢被毁：立即退出（与原版一致）。
- 我方阵亡：先播完 0.4s 爆炸动画再退出（对应原版 `Hero.kill()` 中同步播放爆炸）。

## 五、资源说明

- 资源从 `TankGame/TankWar/resources/` 复制到 `TankGame-CodeBuddy/resources/`（32 个文件：30 图片 + 2 音效）。
- 构建时通过 `POST_BUILD` 自动复制到 exe 输出目录（`build/{Debug,Release}/resources/`）。
- 程序启动时通过 `GetModuleFileName` + `SetCurrentDirectory` 将工作目录定位到 exe 所在目录，保证从任意目录运行都能正确加载资源。
- `tools/` 目录（`auto_draw_map.py`、`resize_img.py`、`map.txt`）为个人辅助工具，不属于游戏本体，未转写。

## 六、错误处理

- 窗口创建失败、D3D11 设备初始化失败、资源加载失败时，通过 `MessageBox` 给出可操作错误信息并返回非零退出码。
- D3D11 硬件设备创建失败时自动回退到 WARP（软件光栅化），保证无独显环境也能运行。

## 七、构建产物

| 配置 | 输出路径 |
|------|---------|
| Debug | `build/Debug/TankGame.exe` |
| Release | `build/Release/TankGame.exe` |

两种配置均已验证编译通过（零错误零警告）并可正常运行。
