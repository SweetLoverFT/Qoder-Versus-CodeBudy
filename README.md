# Qoder-Versus-CodeBudy

当前阶段 2 家智能代理之间的对比，个人观点仅供参考，不代表以后

## 对比最终总结

| 对比项        | 胜出者     | 优势                                                        |
|--------------|-----------|------------------------------------------------------------|
| 综合能力      | CodeBuddy | 易用性：可直接复制为 MarkDown 文本，网络连接稳定；复杂问题处理能力强 |
| 准确性与还原度 | Qoder     | 终于原始要求，对于不合理的问题，会主动问用户是否要求调整，不会擅自修改 |
| 安全性        | Qoder     | 执行所有脚本都会要求用户确认，代价是不便捷，速度慢                  |
| 便捷性        | CodeBuddy | 除非是需要管理员权限、删除操作的脚本才需要用户确认                 |

## 提问

在统一变量的情况下

### 确保提问的公平性

- **对比模型**：确保使用同一模型 **DeepSeek-V4**
- **问题提问的时间和方式**：3 个问题每个前后间隔约 3 天，但是每个问题提问当天，近乎是同一时间对 2 个智能体提问的

### 具体问题

- **日常开发问题**：某个 C# 项目里面，支持 UI 界面国际化（实际测试过，公司项目源码不能透露）
- **网上教程不完整的问题**：要求使用 msvc++ 编译器编译 FFmpeg 音频解码库并做定制（没有用编译的库做验证，只观察实际步骤和效果）
- **综合性复杂工程问题**：plan 模式下，要求使用 C++ DirectX 转写 Python 游戏坦克大战

## 实际表现

- 综合能力 **CodeBuddy** 更好，但是它的**每次回答需要人去认真核实检查**，有的时候会自主告诉你他觉得方案哪方面不好，按照它的想法修改
- Qoder 的**准确性是依托于自主帮你写测试代码、跑验证、分析测试框架输出或者抓图像素对比保证的**，这导致了更多的 token 消耗、更容易钻牛角尖，即触发大模型的死循环，强行终止会导致无法一键完整复制所有回答，只能逐段复制，因此这个智能体是基于 **Looping Engineer**
- 除了第 1 个问题牵涉到公司项目源码，不能泄露具体问答细节和源码，只能给简要结论和智能体思路对比，其他会在对应目录里面，给出具体问答过程

### 日常开发问题：UI 界面国际化

1. **问题补充**：应当准备好贴图资源，再来一次对比测试
2. **问题描述**：整个开发需要使用 C# 和 DevExpress，我需要在软件设置页面里面，添加一个菜单“语言设置”，菜单文字前面要有 Language 的图标，这个菜单悬停后会展开一个二级菜单，二级菜单分别是“简体中文”、“English”，同样的是二级菜单的文字前面要有对应国家的国旗，区别是二级菜单本质上是互斥的 RadioButton，默认要确保“简体中文”是选中的，但是如果程序有配置文件的情况下，需要读取配置文件里面的语言选项（某个属性），从而初始化设置为这个语言并加载对应资源。需要考虑切换的处理
3. **问题潜在难点**：
  - 没有提供国旗图像资源
  - 应用程序切换语言意味着默认需要重启 App，因为操作系统早期设计的时候没有考虑过国际化
4. **个人预期与实际表现**：
  - Language 图标处理：
    - 预期：智能体应当能在 DevExpress 目录下找到对应图片资源，不需要人工提醒
    - 表现：**仅 Qoder 做到**，CodeBuddy 是不是打算程序自绘这点我没留意
  - 国旗图标处理：
    - 预期：智能体应当自主下载统一的、对应的国旗图标，且需要考虑版权、图片有无水印、图片质量和尺寸的统一性
    - 表现：Qoder **连续 3 次自主生成国旗图标**，并修改美国星条旗的星星到比较好的水平，但是**中国国旗的五角星有不明显的错位**，实际上**星星是方块像素点，16x16 的图片看不明显**；CodeBuddy 居然尝试**用 C# code-behind 代码画国旗**，导致代码无法编译通过
  - 应用程序重启处理预期：
    - 预期：先分派延迟启动进程任务，再正确处理应用程序退出与资源释放
    - 表现：代码层面上，2 者无明显差异，但是 **CodeBuddy** 因为自绘问题，无法编译通过所以无法验证
